## 1. What we are building
A **web application for Bangladesh Navy that centrally manages inventory (items, stores, stock) and its allocation/sanction to Ships and Bases**, with role-based access, master data, dashboards and reports.
Procurement itself is **out of scope** — a separate vendor builds **BNPIMS** (procurement); CIMS only *reads* procurement item info from BNPIMS via API.

Authoritative inputs (in priority order):
1. `files_given_by_client/CIMS Final SRS.pdf` — the SRS (35 pp). Modules, users, use cases, data model. Summary: `docs/01-srs-summary.md`.
2. Figma design `https://www.figma.com/design/w8FeXMDCkrCuWua6igdo8M/` — 22 full screens + modals. Extracted spec: `docs/03-figma-ui-spec.md`. This is the **visual source of truth** for the frontend.
3. `files_given_by_client/CIMS_Requiremnets_DSIG.pdf` — Directorate of Signals tender spec (10 scanned pp) for a "Communication Equipment Database Software" (Module 1 comm equipment, Module 2 PABX/telephone). Treated as **one directorate's detailed wish-list** — informs item status lifecycle, TO&E, shortage/notifications, reports, audit log, export. Procurement/budget parts of it are ignored. Summary: `docs/02-dsig-summary.md`.
4. Gap analysis + assumptions we made where sources disagree/miss: `docs/04-gap-analysis.md`. Questions to ask the client: `docs/08-open-questions.md`.

## 2. Locked technical decisions
- **Monorepo**: `backend/` (FastAPI) + `frontend/` (React) + `docs/`. PostgreSQL 16. **No Docker** (client decision 2026-08-17): everything runs natively — local PostgreSQL service, `uvicorn` for the API, Vite dev server / static build for the UI. Deployment = the same three processes on the BN server (systemd + nginx/IIS reverse proxy documented in README).
- **Backend**: Python 3.12+, FastAPI, SQLAlchemy 2.0 **async** (asyncpg), Alembic migrations, Pydantic v2 + pydantic-settings, PyJWT (access 60 min + refresh 7 d), bcrypt password hashing, httpx (BNPIMS client + tests), openpyxl (Excel export), pytest + pytest-asyncio, ruff. Layering: `api/` routers → `services/` business logic → `models/` ORM; `schemas/` Pydantic; `core/` config/security/deps/permissions; `integrations/bnpims.py`.
- **Frontend**: Vite + React 18 + TypeScript, Tailwind CSS (design tokens from Figma in `tailwind.config.ts`), React Router 6, TanStack Query 5, TanStack Table 8, react-hook-form + zod, axios, zustand (auth store), lucide-react icons, recharts (dashboard), @fontsource (Roboto = UI, Poppins = sidebar brand, Barlow = login hero, Inter = modals). Feature-folder structure `src/features/<module>/`.
- **API conventions** (`docs/07-api-conventions.md`): base `/api/v1`; list endpoints accept `page`, `page_size`, `sort=field:asc|desc`, repeated `filter=field:value` (case-insensitive contains) and return `{items,total,page,page_size,pages}` — this powers the Figma table (per-column filter row, sortable headers, pagination, rows-per-page, page-jump+Go). Errors: `{detail}` (FastAPI default) with 400/401/403/404/409/422.
- **RBAC**: `modules` × permissions `menu,list,view,add,edit,delete` per role (= the Figma "Assign Permission" matrix columns Menu/Edit/List/Add/Delete/View). `require_permission(module, action)` dependency; `super_admin` bypasses everything. Sidebar renders only modules with `menu`.
- **User types** (SRS): `super_admin` (seeded at install, cannot be disabled/deleted), `admin`, `office_user` (DTS / Directorate / CINS — recorded in `users.office_id`), `ship_base_user` (bound to `users.ship_base_id`). Users are **never hard-deleted**, only `status=inactive` (SRS). Login by username / email / phone + password. Forgot password = emailed reset link valid **12 h** (SRS; the use-case OTP variant is not implemented).
- **Business codes vs PKs**: every master has an integer `id` PK and a user-entered unique `code` (Figma "Office Code", "Item ID", "Unit ID", "Brand ID", ...). Frontend labels follow Figma; API field is `code`.
- **Status**: masters carry `status: active|inactive` (Figma Active/Inactive radio) where Figma shows it; deletes on referenced rows return 409.
- **Allocation workflow** (see `docs/04-gap-analysis.md` §Workflow): `allocations.status = pending → approved | sent_back | cancelled`. DTS (Allocation/Sanction module) creates → Directorate (Compilation/Verification module) edits/approves or "Demand Back" with a mandatory comment. **Approval deducts stock** from the store (`stock_transactions` ledger, type `allocation_out`; insufficient stock → 409). The check-circle row action on the Allocation list ("Are you sure? You want to Approve this!") calls the same approve endpoint (permission-gated).
- **Stock**: `opening_stocks` entries upsert `stocks(store,item)` and write an `opening` ledger row; `stocks.low_stock_threshold` drives low-stock notifications/dashboard.
- **Fiscal year**: Bangladesh FY July–June, stored as string `"2025-2026"`; `fiscal_years` master seeded; frontend uses a select (Figma drew a date picker — see gap analysis).
- **BNPIMS**: `integrations/bnpims.py` httpx client, base URL + API key from env; `procurement_items` cache table + `POST /procurement-items/sync`. When `BNPIMS_BASE_URL` is empty the client returns deterministic mock data so the screen works. Contract is unknown — adapter isolates it.
- **Audit log** on every create/update/delete/approve (who, what, before/after JSON). Not in SRS but required by DSIG "Monitoring User Action" and sensible for defence.
- **Reports** (Report module): stock summary by store/item, allocations by ship/base & fiscal year, low stock; each supports `?export=xlsx`. Dashboard summary endpoint feeds cards + charts.
- **Never** hardcode secrets; all config through `.env` (see `.env.example`).

Never size a grid by viewport when the sidebar or zoom can change the available width.

## 6. Working conventions
- Backend: `cd backend && uv/pip install -e .[dev]`; run `uvicorn app.main:app --reload`; migrations `alembic revision --autogenerate -m "..."` / `alembic upgrade head`; seed `python -m app.db.seed`; tests `pytest`.
- Frontend: `cd frontend && npm i && npm run dev` (proxy `/api` → `http://localhost:8000`); `npm run build` must pass with zero TS errors.
- Local DB: PostgreSQL 16 service on this machine (`psql` 16.11, superuser `postgres`/`postgres`); app role `cims`/`cims`, DBs `cims` (dev) + `cims_test` (pytest). See `backend/.env.example`. No Docker anywhere.
- Every new module = model + schema + service + router + test (backend) and api fn + hooks + page + route + nav entry (frontend). Follow `brands` (backend) and `features/items/brand` (frontend) as the reference.
- Do not invent requirements silently: when a source is missing/contradictory, decide, implement, and log it in `docs/04-gap-analysis.md` (+ `docs/08-open-questions.md` if the client must confirm).
- Git: the developer commits. Do not commit `files_given_by_client/`, `.env`, `node_modules`, `.venv`, `dist`.
